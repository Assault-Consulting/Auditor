# Security

## Reporting a vulnerability

**Do not** open a public issue or pull request for a security problem.

Use a [private security advisory](https://github.com/Assault-Consulting/Auditor/security/advisories/new),
or contact the maintainers directly. We aim to acknowledge a report within
a few business days and to agree a disclosure timeline with the reporter.

Reports about the PALA-1 **format, codec or verifier** belong upstream, in
[Palimpsests](https://github.com/Assault-Consulting/Palimpsests/security/advisories/new)
— this repository contains no verification logic. If you are unsure which
side a finding falls on, report it here and we will route it.

## Supported versions

Pre-release. Until the first tagged release, only `main` is supported.

## What this application is, from a security standpoint

Auditor is a **read-only desktop viewer** for PALA-1 audit chains. Three
properties define its posture:

1. **It renders verifier output; it does not verify.** Every fact shown
   comes from a `palimpsests` verifier call through one seam module. The
   correctness of a verdict is the upstream package's property, not this
   application's. What *is* this application's property is that it does
   not add, alter or invent a fact along the way — enforced by a CI test
   that fails the build on any wire-parsing primitive outside the seam,
   and by a contract test comparing the sidecar's output to a direct
   reader call.

2. **It never writes to an audited container.** No code path opens a
   `.pala` file for writing, takes a write lock, or re-anchors anything.
   Files are opened read-only. This is an architectural constraint, not a
   convention: a viewer that can damage the evidence it is inspecting is
   worse than no viewer.

3. **It is local-first, and air-gapped by construction in the MVP.** There
   is no network anchor source in the initial release, so there is nothing
   to send anywhere. When network anchor sources are added, they are
   opt-in and gated on two independent layers.

## Trust boundaries

**The sidecar process.** The Python sidecar reads arbitrary file paths on
request, which makes it the most sensitive surface in the application. It:

- binds `127.0.0.1` only — never `0.0.0.0`;
- requires a **per-launch bearer token** generated by the desktop shell
  and delivered to the frontend over IPC. Without it, any local process
  could ask the sidecar to read any file the user can read;
- is spawned and terminated by the shell, and is not intended to be run
  as a standalone service. Running it manually with the token unset
  disables the gate and prints a warning — a development affordance, not
  a supported configuration.

**The webview.** A Content Security Policy is set from the first commit,
not left `null`. The webview may reach exactly one origin: the local
sidecar. This is the first of the two air-gap layers.

**The sidecar's outbound client.** Any request to a non-localhost host is
refused with the caller named. This is the second layer. One layer can be
bypassed by a misconfigured frontend; two cannot.

**Anchor sources.** An anchor is trusted input to a completeness claim.
Auditor never asserts completeness without displaying where the anchor
came from and which sources were tried, skipped or failed. A source that
is present but unreadable is an error with a name, never silently treated
as "no anchor".

## What this application does not claim

- **It does not certify anything.** A report states that this tool checked
  this file against an anchor from this source at this time. It is an
  attestation of a check. It is not a conformity assessment, not a
  compliance certificate, and not evidence that any system meets any
  regulation.
- **It cannot detect what was never written.** A record that a compromised
  host never emitted is invisible to every reader, including this one.
- **It does not establish wall-clock truth.** Chain order is proved; wall
  time is a claim made by the writer and is displayed as such. External
  time evidence exists only when an external witness does.
- **A completeness check is exactly as strong as the anchor source.** An
  anchor the operator can rewrite proves correspondingly little, and the
  UI shows the source so that judgement is possible.
- **It has not been independently audited or penetration-tested.**

## Development-time security controls

- Non-author review on every change, against protected `main`.
- Dependencies declared and monitored by Dependabot across all three
  ecosystems (PyPI, npm, crates.io).
- SAST on every push: Bandit for the sidecar, CodeQL for the frontend,
  `cargo audit` for the shell.
- Least-privilege CI: read-only default token permissions, per-job scopes,
  actions pinned by commit SHA.
- Denial paths are tested explicitly, not just the happy path.
