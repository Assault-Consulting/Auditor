# The language system (L-01…L-05)

Any language is one file. Adding one touches no code.

## How it works

- **Catalogs.** `src/i18n/locales/<bcp47>.json`, one per language, found at
  build time (`import.meta.glob`). English, `en.json`, is the source and
  the fallback. `meta.name` is the language's name for itself, and
  `meta.dir` is `ltr` or `rtl`.
- **Keys, not English.** A key names a screen and a meaning: `bundle.note`,
  `proof.check.holds`. Placeholders are named (`{records}`, `{seq}`), so a
  language may put them in any order.
- **Plurals by the platform.** A plural entry is an object keyed by the CLDR
  categories that `Intl.PluralRules` gives for the language. English has
  `one` and `other`; Ukrainian has `one`, `few`, `many` and `other`. No
  plural rule is written in code. Numbers are formatted by
  `Intl.NumberFormat`.
- **Choosing the language.** The user's choice is used if one is set; it is
  kept in this window's storage on a best-effort basis. Otherwise the first
  of the system's languages that has a catalog (`uk-UA` matches `uk`),
  otherwise English. `<html lang>` and `dir` follow the choice, so screen
  readers switch voice. The picker appears once there are two languages;
  each option is named in its own language.
- **In code.** `t(key, params)` and `tn(key, n, params)` from `src/i18n`.
  They read module state, so the plain functions in `src/api` call them
  directly. `useLocale()` in `App` re-renders the window when the language
  changes.
- **A sentence with an element in it.** `tr(key, parts)` keeps a sentence
  whole when part of it is markup, such as a `<code>` around a hash:
  `"head of the last segment that holds {head}"` with
  `{ head: <code>…</code> }`. The element is a placeholder like any other,
  so a language puts it where its grammar needs it. Sentences are never
  split around an element.
- **Words no language translates** are marked `verbatim(text)`: the
  package's definitions, and the search field's example, whose `kind:` and
  `@` are syntax.

## What is never translated (L-03)

The package's own words are shown as the package wrote them: diagnosis
narratives, advisory and record details, kind and type names, codes, the
verifier's refusal sentences. Only Auditor's sentences around them are
translated. Hashes, seq numbers and paths are never changed. A translation
must not turn a verifier's statement into a different claim.

## The guards (L-04)

- `i18n.test.ts` checks every catalog against English: the same keys, the
  same placeholders in each entry, and every plural form the language
  needs, with none it does not have. A failure names the key.
- `extracted.test.ts` is the ratchet for L-02. It covers every module in
  `src/api`, `state.ts` and `App.tsx`. None of them may keep an English
  sentence in its code. Between JSX tags, even a single word fails, and so
  does a one-word `label:`. The exceptions are the product's name, kind
  names and a file name, each listed in the test. The same test checks that
  every key these modules ask for by name (`t("…")`, `tn`, `tr`) exists in
  English.
- `wording.test.ts` (D-03) also reads every catalog. The intent and
  overclaim rules hold for sentences in JSON as they do for sentences in
  code. Each language brings its own word lists with its catalog (L-05).
- `vocabulary.test.ts` (T11) holds the tables keyed by the package's
  vocabulary, and these now include catalog keys such as
  `scitt.refusal.<code>` and `watch.kind.<kind>`.

## Adding a language (L-05 will expand this)

1. Copy `en.json` to `<tag>.json` and translate the values. Do not change
   keys or placeholders.
2. Give every plural entry the forms your language needs. The test names
   any that are missing.
3. Run `npm test`.
